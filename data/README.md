# DINA starter data — Brighton Beryl GBFS

This folder contains live snapshots of the Brighton Beryl GBFS v2.2 feeds,
flattened into CSV. Each run writes an analysis-ready combined file named
`data_<UTC timestamp>.csv`, so repeated runs build a time series.

Generated by `fetch_gbfs.py` from:

```
https://gbfs.beryl.cc/v2_2/Brighton/gbfs.json
```

## Rebuild the snapshot

From the repository root:

```bash
uv run data/fetch_gbfs.py
```

The script discovers every feed in `gbfs.json`, fetches it, writes the CSVs and
writes a new timestamped combined snapshot such as
`data_20261104T045733Z.csv`. It also refreshes `data.csv` with the latest
snapshot for convenient inspection. It contains no application logic — it is
only the data acquisition step for the talk.

## Files

| File | What it is |
|---|---|
| `data_<UTC timestamp>.csv` | **Combined station-level snapshot** — one file per run, forming the time series. One row per station (119 rows). |
| `data.csv` | Copy of the most recent combined snapshot, for quick inspection and existing demos. |
| `gbfs_feeds.csv` | Feed index discovered from `gbfs.json`, with each feed's `last_updated`, TTL and version. |
| `station_information.csv` | One row per station: name, location, capacity and rental links. |
| `station_status.csv` | One row per station: bikes/docks available, operating flags and nested vehicle counts as JSON. |
| `station_status_vehicle_types.csv` | Long form of the nested counts: `station_id, vehicle_type_id, count`. |
| `free_bike_status.csv` | One row per bike in the free-bike feed (docked and floating), including location, type and range. |
| `geofencing_zones.csv` | One row per geofence, with area and the original GeoJSON geometry. |
| `system_information.csv` | Operator/system metadata, with rental app links flattened. |
| `system_regions.csv` | Region IDs and names. |
| `vehicle_types.csv` | Vehicle type reference data. |
| `system_pricing_plans.csv` | One row per pricing plan, with nested rates/fees as JSON. |
| `system_pricing_plan_rates.csv` | Long form of per-minute pricing. |
| `system_pricing_plan_fees.csv` | Long form of additional fees. |
| `gbfs_versions.csv` | GBFS versions advertised by the system. |

## Combined snapshot columns

**Snapshot context**

- `snapshot_utc`, `snapshot_local` — when the script fetched the feeds.
- `system_id`, `system_name`, `system_timezone` — from `system_information`.
- `station_feed_last_updated*`, `station_feed_age_seconds` — freshness of the
  source `station_status` feed.

**Station identity and location**

- `station_id`, `station_name`, `lat`, `lon`, `capacity`
- `zone_name` — the smallest geofence containing the station (the most specific
  match), or blank if the station is outside all polygons.
- `zone_names` — all containing geofences, smallest first (semicolon separated).
- `rental_uri_android`, `rental_uri_ios`

**Live availability**

- `num_bikes_available`, `num_docks_available`
- `total_docks_reported` — bikes + docks reported (may differ from `capacity`).
- `utilisation_pct` — bikes / capacity × 100.
- `is_empty`, `is_full`
- `is_installed`, `is_renting`, `is_returning`, `is_available`
  (`is_installed AND is_renting`).

**Vehicle mix at the station**

- `bikes_classic`, `bikes_ebike`, `bikes_escooter`, `bikes_cargo`,
  `bikes_other` — classified from `vehicle_types_available` using
  `vehicle_types.csv`.
- `vehicle_types_available_json` — the original nested data, kept for audit.

**Free-bike feed aggregate**

- `free_bikes_in_feed` — bikes in `free_bike_status.csv` naming this station.
- `free_bikes_reserved`, `free_bikes_disabled`
- This feed is a different snapshot from `station_status`, so these counts can
  differ from `num_bikes_available`. That difference is itself useful when
  teaching data-quality checks.

**Timing**

- `last_reported`, `last_reported_utc`, `last_reported_local`
- `reported_age_seconds` — how old the station report was at fetch time.

## Notes and known quirks

- GBFS is a **live snapshot format**. Each run of this script adds one
  `data_<UTC timestamp>.csv` file; run it on a schedule to build a time series.
  Load the series with, for example:

  ```python
  from pathlib import Path
  import pandas as pd

  history = pd.concat(
      [pd.read_csv(path).assign(source_file=path.name)
       for path in sorted(Path("data").glob("data_*.csv"))],
      ignore_index=True,
  )
  ```
- `num_bikes_available + num_docks_available` does not always equal
  `capacity`; Beryl can report unavailable/disabled docks and bikes.
- `free_bike_status` includes bikes that are not available for hire, so a raw
  bike count is not the same as `num_bikes_available`.
- Empty cells in numeric columns mean the field was absent in that feed.
- Geofences overlap. `zone_name` deliberately picks the smallest containing
  polygon so a station inside "George Street" is labelled that, not the larger
  `BTN_Phase_2` zone that also contains it.
